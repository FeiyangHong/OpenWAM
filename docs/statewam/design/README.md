## 决策摘要

重新建立 StateWAM 研究线，以已经验证有效的 OpenWAM 世界骨干和动作专家为基础，研究一个**随世界与动作生成过程更新的交互状态接口**。第一阶段验证这个接口是否改善控制，第二阶段检验未来信息能否通过它传递，第三阶段才考虑蒸馏与减少世界分支计算。

工程开发沿用用户 fork 中已经完成的本体和数据适配；核心消融优先在仿真执行，少量通过筛选的候选进入真机复核。采用“离线/单元检查 → 仿真受控比较 → 真机实际价值验证”的证据链，不要求所有架构变体都上真机。

原版 GR00T/StateWAM 保存为历史基线；不迁移原架构，不沿用 Human 跨域扩展先于机器人验证的门槛。已有数据 QC、物理坐标规范和失败证据继续使用。

本方案没有预设以下结论成立：WAM 普遍优于 VLA、少量状态足以替代世界模型、状态槽天然具有物体/接触语义、确定性 Prior 可以恢复任意示范未来。

## 首轮应当做什么

- 固定 fork 和两条成功训练记录：Pretrain→自有真机数据，以及 Wuji→自有真机数据。
- 保留已成功的真机数据与部署通路，建立仿真基线和独立评测 manifest。
- 实现可完全关闭的 State 通路，验证关闭时与基线数值一致。
- 先在 RoboTwin 比较容量匹配的当前状态通路与未来交互状态通路，再把少量候选带到真机。
- 只有出现控制收益，才扩大监督、数据规模或压缩力度。

## 已有材料与本次工作边界

原版结果来自用户提供的 `StateWAM_Current_and_OpenWAM_Findings_2026-09-12.md`，本次没有重新审计其原始实验日志。用户进一步确认：在自己的 fork 中，分别以 OpenWAM Pretrain model 与 Wuji model 为初始化，使用自有真机数据训练，效果都非常好。这是已经成功的下游适配证据，不是原始权重零样本部署结论，也没有提供两类初始化的严格胜负排序。

同级 `StateWAM-v2/` 是前次下载的官方研究副本，只作上游参考；本次另取 `OpenWAM-FeiyangHong-reference/` 核对用户 fork。二者均未修改模型代码。后续实现应从用户 fork 的已验证提交建立新分支；不需要重新迁移 Wuji 适配。这里的 StateWAM 类名和配置是下一阶段规格，不表示功能已经存在。

## 已确认资源与待填事实

用户已确认可用 **8–16 张 80 GB A100**，效果成立后可申请几十卡；真机候选为**天机/星尘机械臂 + 舞肌/Sharpa 灵巧手**。计划采用预训练模型上的系统性微调与消融，优先选择已经跑通的一种实际组合，其余作为跨硬件验证。

已核对 fork 的 Wuji/Astribot 适配包含三视角、58D raw→80D model 映射与 rot6d 转换；不能把该契约自动推广到其他手臂/手组合。仍需填入：实际运行配置、两类源权重和已训练输出的校验值、数据总量与 split、控制频率、部署 GPU/延迟预算、仿真环境是否已安装。训练时长待 profiling 后估计。

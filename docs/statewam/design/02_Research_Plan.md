日期：2026-09-12\
修订：v2，用户 fork + 两类初始化 + 仿真优先。\
状态：新版 StateWAM 的效果与资源开销尚未测量；用户的 OpenWAM 真机训练已有成功经验。

## 0. 六阶段总览与仿真/真机分工

| 阶段 | 主要场所 | 主要交付 |
|---|---|---|
| R0：固定真实基线与仿真协议 | 现有真机记录 + 仿真环境 | fork/两类权重/数据契约，以及仿真基线 |
| R1：实现最小架构 | 离线、真实权重、仿真 smoke | State 开关、梯度、checkpoint、推理一致性 |
| R2：结构受控比较 | RoboTwin 优先 | E0–E3 的闭环结构证据 |
| R3：机制与稳健性 | 仿真 + 离线 probe | 状态来源、更新、容量、瓶颈与扰动实验 |
| R4：自有真机复核 | 已跑通的机械臂+灵巧手 | 少量候选在 Foundation/Wuji 初始化下的实际效果 |
| R5：扩展 | 按瓶颈选择 | 跨硬件、数据规模或部署效率 |

这里的“仿真优先”指核心消融与模型筛选，不否认或重做用户已经完成的真机训练。真实数据接口与少量部署 smoke 可以尽早检查，但不再让每个 State 变体都消耗大规模真机试验。

## 1. 资源和平台约束

用户已确认：**8–16 张 80 GB A100**，若效果好可申请扩展到几十张卡。真机候选是**天机机械臂或星尘机械臂，搭配舞肌灵巧手或 Sharpa 灵巧手**。

本计划据此采用预训练 checkpoint 上的完整模型微调/部分参数微调，不从零重训大型世界模型。8 卡完成主要模型与首轮消融，16 卡用于复核、并行独立实验或后续数据扩展；几十卡申请须有可重复真机收益作为依据。显存可行性仍须在真实视频几何、动作长度和优化器配置下 profiling，卡数本身不是吞吐保证。

工程底座为 [FeiyangHong/OpenWAM](https://github.com/FeiyangHong/OpenWAM)，本次核对 HEAD `5be50682eb45ef5d2dace77cce88c3baa0c48446`。fork 已包含 Wuji/Astribot 数据适配；首轮真机复核选择已经成功的实际组合，其余组合保持扩展状态。

用户已确认：分别从 OpenWAM Pretrain 和 Wuji model 出发，用自有真机数据训练，效果都很好。对应 fork 文档列出 Foundation 与 Real-Dexterous-Hand-Wuji 两个模型名称。已成功的是两条下游训练路线，不是原始模型的零样本成绩；具体源权重/输出权重、运行配置、数据曝光仍应入档。

仍待填入：机器人数据量与任务数、采集频率、失败数据比例、已复现 checkpoint/代码 SHA、相机布局、手部和机械臂控制接口、部署计算硬件、目标响应延迟。以下任务数和步数是可修改的实验起点，不是对现有数据的描述。

## 2. 主假设、主要指标与报告层级

主假设分两层：**机制层**在相同仿真数据、初始化与预算下验证交互状态的闭环收益；**外部有效性层**检验选定结构在自有真机数据和本体上能否保留有价值的改进。两层结果不合并成一个总成功率。

主要指标：每个预定义 task×condition 单元的成功率，按单元等权平均。失败、中止、超时和人工接管按预先规则计入；不要通过每组不同的重试次数改变成功定义。

次要指标：抓取/释放/操作阶段完成率、物体滑脱或掉落、对位误差、扰动后的恢复、人工接管次数、任务完成时间，以及部署 p50/p95 端到端延迟。

研究结论分级：

| 层级 | 可以报告 | 不能外推 |
|---|---|---|
| 工程正确 | loss/梯度/加载/推理通过检查 | 模型会操作或泛化 |
| 仿真 pilot | 在固定协议中出现筛选信号 | 真机一定有效 |
| 仿真保留测试集 | 在给定环境/初始状态分布上的结构效果 | 真实接触、滑脱或手指协调已验证 |
| 真机复核 | 在自有数据适配和实际平台上的收益 | WAM 普遍优于 VLA |
| 跨硬件与数据扩展 | 在明确适配协议下保留收益 | 未测试硬件零样本泛化 |

## 3. 阶段 R0：固定真实基线与仿真协议

### 工作

1. 固定用户 fork 上两类成功 run：各自源 checkpoint、训练后输出、代码提交、数据和解析后配置、统计、图像处理、噪声步数和执行器。
2. 保留 fork 的本体适配，不另从官方仓库重做。当前 HEAD 仅为源码核对点，历史成功 run 可以位于更早提交。
3. 明确机械臂 action 是关节、EEF 还是其他控制量；明确手部 action 是关节角、协同控制还是其他命令。记录每个槽的单位、顺序、左右约定与有效性。
4. 对相机、机械臂、手部数据做时间戳对齐，记录执行延迟；action 的时间与观察时间关系不能靠数组索引猜测。
5. 先按 episode/session/object instance 等划分 train/validation/test，再取窗口、计算统计和教师缓存。
6. 使用已有真机记录并补少量必要 rollout，建立失败分类；不把“重新大规模证明 OpenWAM 好用”当作新架构前置任务。
7. 固定 RoboTwin 环境版本、训练 split、评测任务/初始状态与 policy server 配置，先复现仿真 E0。仿真配置详见 [独立协议](04_Simulation_Protocol.md)。

### 两条初始化路线

| 记录 | 含义 | 用途 |
|---|---|---|
| F0 / W0 | Foundation / Wuji 源模型 | 明确初始化身份 |
| F-real / W-real | 用户从 F0/W0 用自有数据训练的结果 | 已有成功实证和工程基线 |
| F-sim-Ei | 从 F0 在同一仿真训练集微调的 E0–E3 | 仿真主矩阵 |
| F-real-Ei / W-real-Ei | 从 F0/W0 在同一真机训练集训练的候选 | R4 内部配对比较 |

已有 F-real/W-real 可以用于 smoke 或所有组同等追加训练的实验，但其历史训练曝光必须计入。正式独立测试不得包含这些权重已经训练过的数据/场景实例。

### 灵巧手平台的特别要求

- 抓取成功与操纵成功分开计分；仅手指闭合不算成功抓取。
- 第一轮用“抓住后物体保持、抬升、放置/操作结果”等可观察标准标注交互状态。
- 不预设舞肌或 Sharpa 的自由度、驱动接口、触觉可用性、控制频率，也不假定它们的 action slot 直接兼容。
- 当前已核对的是 fork 的 Wuji/Astribot raw 58D 数据契约；20 维 hand block 是此数据表示，不是其他手的物理自由度声明。
- 若使用 80-D 统一动作空间，逐槽检查覆盖性；实际维度超出预留语义时应明确扩展/适配，不截断、不补零伪装为同一动作。
- 如果已有触觉/力信息，先不单独给新模型使用；保持输入匹配，之后作为独立实验因素。
- 保留现有机器人速度/力矩限制、工作区保护和人工急停流程，自动策略不绕过底层控制约束。

### 通过条件

已有真实训练证据与契约入档；仿真 E0 可运行、初始化与评测状态可记录。若某一轨道不能复现，先诊断该轨道，不否定另一个轨道的已有成功。State 结构优劣比较必须在各自已稳定的基线上进行。

## 4. 阶段 R1：工程最小闭环

首个实现只包含 Residual-State、Current-State 容量对照、开关与必要诊断；语义教师、Human 扩展、独立 Prior 和蒸馏均关闭。

### 检查顺序

1. 小张量 CPU 测试：shape、mask、梯度、checkpoint 参数注册。
2. 单卡真实权重 smoke：一个实际 batch 的预处理、forward、backward、保存、重载、推理。
3. 8 卡以实际几何 profiling，先运行 200–500 个**优化器更新步**测显存、吞吐、梯度与 checkpoint 开销。
4. State 关闭及 gate=0 时，使用相同输入与噪声比较基线输出；先 eager，再编译。
5. 梯度累积、padding、无动作样本和 mask 检查通过后，做短仿真 rollout；在实际真机数据 batch 上同步检查接口，不要求新模型已经有真机增益。

### 关键验收

- 初始残差为零时，在预先规定的精度容差内与原模型输出一致。
- gate 第一步能够学习，后续 reader/writer 均获得非零有限梯度；不能只看到 loss 下降。
- checkpoint 中含新增参数，重载后同输入输出一致，resume 恢复优化器状态。
- State 不读取任何额外干净未来标签；teacher target 不进入 deploy condition。
- 当前视觉 token 不受 future/action/State 污染。
- baseline 与新模型的相机、动作归一化、执行步数与控制频率一致。

工程通过不计为研究 PASS。

## 5. 阶段 R2：仿真中的首轮结构实验

主比较使用 RoboTwin，默认优先 Clean2Random：所有组只在 clean 训练，分别评估 clean 与 randomized。Full 使用 clean+randomized 训练，是单独的 ID/拟合协议。不能把 Full checkpoint 当作 Clean2Random 的“未见随机场景”基线。

LIBERO 可用于较低门槛的接口 smoke；LIBERO/LIBERO-plus 在候选减少后补充单臂与视觉扰动验证。不要同时铺开多个 benchmark 的全部网格。现有仿真以其原生末端执行器为准，不为首轮构建舞肌/Sharpa 数字孪生。

### 最小模型矩阵

| ID | 配置 | State 读取来源 | 首轮用途 |
|---|---|---|---|
| E0 | 原 OpenWAM，追加同预算训练 | 无 | 主基线 |
| E1 | Current-State residual | 仅当前视觉、语言、有效 proprio | 容量/附加通路对照 |
| E2 | Future-State residual | 当前条件 + 未来 world，不读动作 hidden | 未来来源实验 |
| E3 | Interaction-State residual | 当前条件 + 未来 world + 动作 hidden | 主候选 |

所有 E0–E3 默认从同一 F0 在相同仿真数据上训练。先用一个训练种子筛选，再对 E0、E1 与最佳未来状态模型补充至少三个训练种子的复核。这里的三个种子指训练重复，不是仅改变评测 reset seed。不能只比较 E0/E3 就宣称 world knowledge 增益。

准确地说，E2/E3 隔离的是额外的**直接 action→State 边**；两者的 Wf 都可能通过原 mutual 骨干含有动作信息，不据此声称排除了全部动作反馈。

### 参数与预算匹配

- 采用相同 F0、同一仿真 robot train split、相同数据次序/增强种子策略、相同优化器更新步与有效 batch；published simulation checkpoint 只作 smoke/协议参照，除非所有组共同从它继续训练且训练曝光明确。
- E0 必须接受相同追加训练，不能拿新模型微调结果对比未经同等微调的旧 checkpoint。
- E1 与 E2/E3 尽量匹配 reader/writer 参数与 attention 工作量；无法精确匹配时报告差异，并增加同等参数 MLP/current branch 对照。
- 固定 world/action 参数更新策略。若采用参数冻结适配，所有对照遵循相同策略；追加一个可训练 ActionDiT 的基线，避免把低适配能力基线作为主比较。
- 同时报告 step-matched 和 GPU-hour 消耗；新增模块的额外计算不能隐去。

### 训练策略

首选：新增 State 模块 + ActionDiT 可训练；世界骨干先采用**参数冻结但保留输入梯度**的短适配，再视显存/效果解冻，或者直接使用已验证的全量微调配方。两者不能在主比较各组中混用。

建议先沿用已跑通的优化器与 batch。若缺乏配方，State 学习率可从 `1e-4`、ActionDiT 从 `1e-5`、world 从 `0` 或 `1e-6` 起做小范围验证；这些只是启动值。world=`0` 不能用整个 forward 的 `no_grad` 替代参数冻结，否则可能切断新增通路梯度。

零初始化 gate 的短启动期后检查 State 梯度；若增益来自 gate 始终为零，则模型实际没有利用新通路。

### 仿真 pilot 建议

预先选定约 10 个覆盖不同交互类型的任务，避免只挑基线最弱或新模型最强的任务。每模型以 10 task×2 condition×20 个初始状态评估，约 400 rollout/model；四模型约 1600 次。这是筛选预算，不是足够检测小效应的保证。

同一 task/condition 内，模型使用配对的环境初始状态、任务指令和随机化参数；策略噪声单独记录。区分训练种子、环境种子和策略采样种子。GPU/物理引擎不一定逐位确定，需要重复少量基线 rollout 量化残余随机性。

真机在此阶段只做少量数据/部署 smoke，或者极少数有明确灵巧手机制理由的 pilot，不承担 E0–E3 的主筛选。

### 推进/停止

- 主候选未超过 E1：优先检查参数/优化收益，不宣称未来交互有效。
- E2 与 E3 接近：保留更简单的 E2，动作反馈不作为必要机制。
- E0 已有明显天花板：增加预先定义的难度或扰动集，不能只放大百分比相对提升。
- 多个种子均无信号：停止扩大 State 规模与新数据，回到失败分类和目标设计。若怀疑基准缺少目标灵巧手机制，先定义一个与该机制相关的任务再做小规模补充，不通过反复换 benchmark 追逐正结果。

## 6. 阶段 R3：仿真机制与稳健性复核

仅在 R2 有信号后，逐项测试，不进行全因子网格。

K、更新频率、信息流 mask、bottleneck 与语义 loss 的主要消融在仿真完成。额外接触/物体姿态等仿真真值默认只用于 probe 和机制评测；若用于训练，必须单列 privileged-supervision 实验并给所有对照同等标签，不能混入可直接部署的主配置。

| 实验 | 对照必须保持什么 | 能回答什么 |
|---|---|---|
| S0：加真实未来 semantic loss | 相同教师、数据和预算；加 E1+同目标对照 | 语义监督是否改善控制，而非只改善 probe |
| S1：dynamic vs single-read | 相同训练条件；说明计算差异 | 持续更新是否必要 |
| S2：future bottleneck | 从相同初始化适配；当前视觉始终可见 | State 能否承载动作需要的未来信息 |
| S3：K=8/16/32 | 只在获胜架构上扫描 | 容量与性能关系 |
| S4：控制中的特征干预 | 保持当前条件与噪声；匹配/重训练对照 | 哪条信息来源被利用 |

单次 inference 置零或打乱可能制造分布外输入，依赖性损失不是充分的因果归因。必须与完整训练的无该来源模型结合解释。

状态 probe 采用训练集训练、held-out episode 测试；报告 current-only baseline。对于抓取、滑脱、相对位置和接触类问题，用独立标签评估，不用教师自身输出同时当训练目标与唯一真值。

高噪声、低噪声、完整闭环采样的 probe 分开报告。错误 instruction 实验只在同一观察下确实存在多个可执行目标的条件中评价语义影响；如果任务已被场景唯一确定，不能据此否定语言使用。

选定模型后，在独立仿真测试种子上复核；LIBERO-plus 用来检查视觉扰动，并不代表真实灵巧手摩擦/接触行为。仿真接触真值是引擎状态，不是现实真值。

## 7. 阶段 R4：少量候选的真机复核

默认把一个胜出 StateWAM 结构带到真机，与同初始化、同数据预算的 OpenWAM 比较。若要在真实平台声称超越额外容量，再加入 E1；不把所有 K/更新频率/语义 loss 组合重新上机。

在 Foundation 与 Wuji 两条初始化内分别比较：`F0→OpenWAM / F0→StateWAM`，`W0→OpenWAM / W0→StateWAM`。两条都已被用户证明能通过自有数据获得好效果，既不预先认定 Wuji 更强，也不要求把初始化×架构×全部消融做成完整网格。预算不足可先冻结一条主初始化，另一条只复核最终两模型。

默认从 F0/W0 对相同真机训练集训练，不强制继承仿真微调后的权重。这样检验的是架构效果能否在真实数据学习中保留；若额外使用 sim→real 权重迁移，应作为独立训练因素并匹配对照。

### 测试条件分开定义

| 条件 | 具体变化 | 要避免的混淆 |
|---|---|---|
| ID | 同任务分布，新 episode 与初始状态 | 重复训练窗口 |
| 视觉扰动 | 背景、照明、相机位置分别测试 | 一次同时改变所有因素 |
| 物体/布局 | 新实例、位置或容器关系 | 未记录的训练集相似物体 |
| 交互扰动 | 可控滑移、执行偏差、可恢复位置偏差 | 对不同模型施加不同扰动 |
| 新硬件 | 第二种机械臂或灵巧手组合 | 控制器、数据量与模型机制一起改变 |

初轮建议选择 3–4 个现有数据支持的任务，覆盖抓取稳定性、操作/对位和手指协调中的可执行内容；ID + 一种主要 OOD 即可起步。第二硬件组合移到 R5，可避免把新控制器适配引入首轮真机比较。

### 样本量与统计

起始工程 pilot 可为 4 task×2 condition×10 次 reset = 80 次/model/初始化；两个模型在一个初始化中共 160 次，两条初始化共 320 次。它只用于判断效果是否可用、识别方差与失败模式。

正式样本量按 pilot 方差与预定最小收益计算。不要机械执行上一版每个模型数百次的全套矩阵，也不要以减少真机随机性为由只展示少量成功视频。需要统计主张时，把试验预算集中在最关键的少量模型。

仿真多训练种子不能替代真机训练重复。关键真机比较尽量包含 2–3 个训练 seed；预算只允许单 seed 时明确标为初步真实验证，不用大量 reset 假装已经验证训练稳定性。

真机不要求精确重建同一物理初态。采用场景模板、位置范围/夹具和按 session/day 分块的交错顺序，记录实际初始图像、姿态、物体状态与手部标定；条件明显不合格时按预先规则重置，而不是事后只剔除某个模型的失败。

成功/失败判定尽量按匿名 rollout 视频和固定判据完成；争议案例记录仲裁规则。不要让评估者知道模型名称后使用不同的成功宽容度。

成功率差为主要统计量，报告绝对百分点、区间和每任务结果。真机采用 task/session/训练 seed 的分块或分层分析；仅在确有设计依据时使用成对分析，不能把近似相同的场景当成仿真式精确配对。bootstrap 不能把帧、窗口或同一 episode 的动作当独立样本。

### 预先约定的判断方式

- **能力改进路线：**主指标差的区间支持正增益，且达到预定实际价值。可暂以 +5 个百分点作为讨论起点，但应在看最终结果前，结合基线成功率和任务成本冻结阈值。
- **效率路线：**预先设定非劣界（例如 -5 个百分点，仅为起点），同时证明实际端到端延迟/显存收益。不能用“不显著下降”代替非劣性检验。
- **分组结果：**一个预定义重要扰动上改善、总体不变，可以报告该条件的收益，不扩写为整体泛化。
- **失效：**出现新的严重掉落、碰撞风险或关键任务退化，应记录并分析，不能只用平均成功率抵消。

模型选择只用 validation。保留测试集的首次正式结果用于最终判断；若据此改模型，原测试集转为开发集，另建独立复核集。

### 跨硬件顺序（R5 条件性扩展）

先固定机械臂、换灵巧手，或者固定灵巧手、换机械臂，取实际可接通的一项；每次只改变一个主要硬件因素。

按相同目标硬件数据预算比较基础 OpenWAM 与 StateWAM，区分零样本、少样本微调和全量微调。动作适配、手部关节语义、相机位置和 proprio mask 的变化需独立记录。

没有第二套硬件完整数据与部署接口时，跨硬件研究保持计划状态，不阻塞第一平台的主结论。

## 8. 阶段 R5：数据扩展或压缩，二选一优先推进

### 数据扩展路线

当主要缺口是物体/场景覆盖时，先比较 robot-only 与固定总预算的 robot+human 混合。分别记录帧数、动作标注量与 GPU-hours；混合数据减少机器人监督时，设置额外机器人数据量匹配对照。

Human 数据只通过有效目标更新；HoloAssist 最多作为受审计的一个来源。看目标机器人闭环指标，不把人类 probe 改善作为扩容标准。

建议先 8 卡做小混合对照，再 16 卡验证规模趋势。只有有正向 transfer 且训练稳定，才申请几十卡。扩展算力用于已经成立的配方，不用于掩盖尚未解释的负迁移。

### 压缩路线

当 State bottleneck 可保留控制表现、部署成本成为瓶颈时，再训练轻量学生、减少 world 计算或降低读取频率。学生应在仅部署可得输入下评估；教师真实未来 oracle 与教师部署 rollout 的监督要分开。

必须复测闭环成功率、扰动恢复和端到端 latency。K 变小只表示接口更窄，不表示 5B world backbone 已被省去。

## 9. 计算预算的记账方法

先测 8 卡 steady-state 优化步时间 \(t_{step}\)、有效样本吞吐、数据读取比例和 checkpoint 时间，再估算每个 run：

\[
T_{run}=T_{load}+N_{opt}\,t_{step}+T_{eval}+T_{save}
\]

\[
GPU\text{-hours}=N_{GPU}\times T_{run}(hours)
\]

上游 trainer 的 `max_steps` 按 micro-step 计数；实验表统一写 optimizer updates，同时存储 gradient accumulation、micro-step、global batch 与样本曝光数，避免预算错配。

资源安排：

| 阶段 | 默认资源 | 扩展条件 |
|---|---|---|
| 接口/真实权重 smoke | CPU + 1–2 卡，按装载实测 | 无需大规模训练 |
| 仿真 E0–E3 | 每 run 8×A100 80G，先单 seed | 稳定后补 seed |
| 仿真评估 | 独立调度 policy server 与环境/render worker | 先测 A100 驱动的渲染能力与吞吐 |
| 机制/真机微调 | 8–16 卡；可同时运行两个 8 卡 run | 不让仿真评估抢占完整训练卡组 |
| 跨硬件与规模验证 | 16 卡优先 | 有稳定 transfer 信号 |
| 几十卡扩展 | 不纳入启动必需条件 | 已有真机增益、规模趋势和明确瓶颈 |

不要直接套用论文或其他显卡的推理毫秒数。部署 GPU 尚未给定，延迟预算必须在实际部署设备测量。

## 10. 里程碑与最终交付

| 里程碑 | 交付件 | 是否解锁下一阶段 |
|---|---|---|
| M0 | fork/两类真实训练 manifest、数据契约、仿真基线 | 是，保留已有真机证据 |
| M1 | State 开关、梯度/加载/部署测试与 profile | 是，仅工程解锁 |
| M2 | 仿真 E0/E1/E2/E3 对照与失败分析 | 筛选结构 |
| M3 | 仿真独立测试集、多 seed、机制与稳健性 | 少量候选进入真机 |
| M4 | Foundation/Wuji 下的真机复核 | 界定实际价值 |
| M5 | 一项跨硬件/混合数据/效率扩展 | 按主瓶颈选择 |

不按未知吞吐承诺固定周数。每阶段开始时根据已测资源与真机可用时间排期。最早的关键研究决策点是 M2，不是完成所有模块之后。

每个正式结果至少保存：配置与代码 SHA、初始化权重、数据 split manifest、训练/增强/采样种子、优化步/样本量/GPU-hours、归一化与时间戳契约、每次 rollout 的结果/视频/失败分类、分析脚本版本和完整置信区间。

## 11. 首次立项时应冻结的六项

1. 主平台实际机械臂+灵巧手组合及动作接口。
2. 用户 fork 的成功 run 提交、F0/W0 源权重与训练输出。
3. 仿真与真机分别独立的 train/validation/test manifest。
4. 仿真 task/reset/随机化协议，以及真机 3–4 个起始任务与成功条件。
5. 第一轮每个 run 的优化步/样本曝光/GPU-hour 上限。
6. 主要指标、实际收益阈值、样本量和停止条件。

这些是执行计划的待填项目事实，不影响本次结构方案交付。
